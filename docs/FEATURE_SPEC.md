# OSS Tech-Radar 기능 명세 (v2)

> 목표: **"GitHub 오픈소스 생태계에서 지금 무엇이 뜨고 있는가?"** 를
> 개발자가 아닌 사람도 3초 안에 파악할 수 있는 트렌드 사이트.

---

## 1. 기존 버전 진단 (v1의 문제점)

| # | 문제 | 사용자 영향 |
|---|------|-------------|
| 1 | 사이드바 링크에 `domain` 이 붙지 않음 → 페이지 이동 시 항상 `frontend` 로 리셋. 헤더 셀렉터는 이전 도메인을 표시해 **화면과 데이터가 불일치** | "Backend 골랐는데 왜 Frontend 데이터가 나오지?" |
| 2 | 대시보드/상세가 항상 **"이번 달"** 을 조회. 크롤링은 매일 03시라 월초에는 데이터가 비어 보임 | 매달 1일엔 빈 화면 |
| 3 | `Active Level Score`, `S/A/B/C 등급`, `사용 수` 등 **용어 설명 없음** | 숫자의 의미를 알 수 없음 |
| 4 | 데이터가 없을 때 "데이터가 없습니다" 만 표시. 크롤링/리포트 생성 API 는 있는데 UI 에 없음 | 첫 실행 시 무엇을 해야 할지 모름 |
| 5 | 라이브러리 상세의 "도메인 Top 레포지토리" 는 **해당 라이브러리와 무관한 데이터** | 오해 유발 |
| 6 | 필터/정렬/검색 상태가 URL 에 남지 않음 | 공유·새로고침 시 초기화 |
| 7 | 전역 검색 없음, 테이블이 모바일에서 가로 스크롤 | 탐색 불편 |
| 8 | 사이드바 활성 표시가 하위 경로(`/libraries/react`)에서 꺼짐 | 현재 위치 파악 어려움 |

## 2. 정보 구조 (IA)

```
OSS Tech-Radar
├── 홈 (트렌드 한눈에)           /
├── 라이브러리 랭킹              /libraries
│   └── 라이브러리 상세          /libraries/[name]
├── 프로젝트 활성도              /repositories
├── AI 월간 리포트               /reports
│   └── 리포트 상세              /reports/[id]
└── 이용 가이드                  /guide
```

**전역 요소**

- **분야(도메인) 바** — 모든 페이지 상단에 칩 형태로 항상 노출. 선택값은 URL(`?domain=`) + 쿠키에 저장되어
  어느 페이지로 이동해도 유지됨.
- **빠른 검색 (⌘K / Ctrl+K)** — 페이지 이동, 라이브러리·프로젝트 이름 검색, 분야 전환.
- **반응형 내비게이션** — 데스크탑: 좌측 사이드바 / 모바일: 하단 탭바.
- **라이트/다크/시스템 테마**.

## 3. 화면별 기능 명세

### 3.1 홈 — 트렌드 한눈에 (`/`)

| 영역 | 내용 | 비고 |
|------|------|------|
| 히어로 요약 | "이번 달 **Frontend** 분야에서 가장 빠르게 성장한 라이브러리는 **vite (+42%)**" 같은 **자동 요약 문장** + 데이터 기준월·분석 프로젝트 수 | 숫자보다 문장을 먼저 |
| 핵심 지표 4개 | 분석한 프로젝트 / 추적 중인 라이브러리 / 새로 등장한 라이브러리 / 매우 활발한 프로젝트 | 각 카드에 ⓘ 설명 |
| 🔥 급상승 TOP 5 | 전월 대비 증가율 상위 (신규 제외) | 클릭 → 상세 |
| ✨ 새로 등장 | 전월 0 → 이번 달 등장 | 칩 목록 |
| 📉 주춤한 라이브러리 | 증가율 하위 5 | |
| 🏆 가장 많이 쓰는 TOP 10 | 사용 프로젝트 수 + **채택률(%)** 막대 | |
| ⚡ 가장 활발한 프로젝트 TOP 5 | 활성도 점수·등급 | |
| 활성도 분포 차트 | Stars × 활성도 산점도 + 등급 범례 | |
| 최신 AI 리포트 | 최신 리포트 카드 | |
| 빈 상태 | 데이터가 없으면 **"데이터 수집 시작"** 버튼 + 소요 시간 안내 | `POST /crawl/trigger` |

**기준월 규칙**: `GET /libraries/months` 로 데이터가 있는 가장 최근 월을 자동 선택 (신규 API).

### 3.2 라이브러리 랭킹 (`/libraries`)

- **검색** (`q`), **기준월** (`month`, 데이터 있는 월만 노출), **정렬** (`sort`: 사용량/성장률/전월),
  **빠른 필터** (`filter`: 전체 · 🔥급상승 · ✨신규 · 📉하락) — 모두 URL 에 저장 → 공유 가능.
- 각 행: 순위, 이름, 생태계 태그(npm / Maven / PyPI 추정), 사용 프로젝트 수 + 상대 막대, 채택률, 전월 대비.
- 모바일에서는 카드 리스트로 전환.

### 3.3 라이브러리 상세 (`/libraries/[name]`)

- 지표: 사용 프로젝트 수 / 분야 내 순위 / 채택률 / 전월 대비.
- 최근 6개월 추이 영역 차트.
- 외부 링크: 패키지 레지스트리(npm·Maven Central·PyPI), GitHub 검색.
- 같은 분야 인기 라이브러리 (이동용).
- ~~도메인 Top 레포지토리~~ → 라이브러리와 무관하므로 **제거**.

### 3.4 프로젝트 활성도 (`/repositories`)

- 검색(`q`), 정렬(`sort`: 활성도/Stars), 등급 필터(`grade`), 언어 필터(`lang`) — URL 저장.
- 등급 범례를 화면 상단에 상시 표시 (S 매우 활발 / A 활발 / B 보통 / C 낮음).
- 각 항목: 이름(GitHub 링크), 언어, Stars, Forks, 30일 커밋·PR·이슈 처리량, 점수, 등급.

### 3.5 AI 월간 리포트 (`/reports`, `/reports/[id]`)

- 분야 필터 탭(전체 + 6개 분야), 최신순 카드.
- 리포트가 없으면 현재 분야로 **"리포트 생성"** 버튼 (Claude API 키 필요 안내).
- 상세: 읽는 시간, 링크 복사, 이전/다음 리포트.

### 3.6 이용 가이드 (`/guide`)

- 사이트 소개 / 데이터 수집 방식 / 지표 계산식(사용 프로젝트 수, 성장률, 채택률, 활성도 점수·등급) /
  업데이트 주기 / FAQ.

## 4. 용어 정의 (UI 전역에서 동일하게 사용)

| UI 용어 | 정의 | 원본 필드 |
|---------|------|-----------|
| 분야 | frontend · backend · devops · mobile · data · security | `domain` |
| 사용 프로젝트 수 | 해당 월 분석한 프로젝트 중 의존성 파일에 이 라이브러리가 있는 프로젝트 수 | `usageCount` |
| 채택률 | 사용 프로젝트 수 ÷ 분석한 프로젝트 수 | 계산값 |
| 전월 대비 | (이번 달 − 지난달) ÷ 지난달 × 100 | `growthRate` |
| 신규 | 지난달 0 → 이번 달 1 이상 | `prevMonthCount == 0` |
| 활성도 점수 | (30일 커밋×3 + 병합 PR×2 + 닫힌 이슈×1) ÷ ln(Stars+1) | `score` |
| 등급 | S ≥ 50 · A ≥ 20 · B ≥ 5 · C < 5 | 계산값 |

## 5. API 변경 사항

| Method | Path | 변경 |
|--------|------|------|
| GET | `/api/v1/libraries/months?domain=` | **신규** — 데이터가 있는 월 목록 (최신순, `YYYY-MM[]`) |

나머지 엔드포인트는 그대로 사용.

**버그 수정** — `LibraryUsageRepository` / `MonthlyReportRepository` 조회 메서드가 `YearMonth` 필드에
`LocalDate` 파라미터를 넘겨 `QueryArgumentException` 이 발생하던 문제 수정
(`GET /libraries` 500 오류, 크롤링 후 라이브러리 집계 실패, 리포트 생성 실패의 원인).

## 6. UI/UX 원칙

1. **문장 먼저, 숫자는 다음** — 요약 문장과 이모지 섹션 제목으로 맥락 제공.
2. **모든 지표에 ⓘ 설명** — 마우스 오버/포커스 시 정의 표시.
3. **빈 상태는 다음 행동을 제시** — "없음" 대신 버튼과 안내.
4. **상태는 URL 에** — 필터·정렬·검색·분야 모두 공유 가능.
5. **모던 비주얼** — Pretendard 폰트, 넉넉한 여백, 2xl 라운드 카드, 은은한 그라데이션, 글래스 헤더,
   다크모드 완전 지원, 모바일 하단 탭바, 키보드 접근성(포커스 링, ⌘K).
